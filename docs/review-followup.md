# Review follow-up

All 15 review points were evaluated against the implementation and regression tests. Reproducible correctness issues are fixed in the same audit PR. The choices below distinguish code defects from configuration requirements and harmless output differences.

| Review point                                       | Resolution and evidence                                                                                                                                                                                                                                                                                                                                                                                               |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Legacy validation origin changes in development | Preserve `validate.baseUrl` alone as the document origin. A regression uses an HTTPS `Astro.site` with an HTTP development URL and checks that first-party scripts do not get false SRI warnings.                                                                                                                                                                                                                     |
| 2. Version gate excludes Astro 5 CSP               | Feature-detect the API. Packed Astro 5 consumers build with CSP disabled and enabled; enabled builds contain the correct final-content hash. Only `CspNotEnabled` is suppressed.                                                                                                                                                                                                                                      |
| 3. Manual first base loses precedence              | Explicit `options.baseUrl` describes the effective browser base and wins over Helmet's base. All three browser engines load scripts and styles with a manual first base and a conflicting later Helmet base.                                                                                                                                                                                                          |
| 4. Undefined validation fields erase context       | Undefined fields no longer overwrite the component defaults. An explicit validation document origin remains an intentional validation-only override, now documented and tested.                                                                                                                                                                                                                                       |
| 5. Validation and CSP resolve bases differently    | Share URL resolution, including relative bases and the document origin. Absolute resources receive SRI checks even with a malformed base. Invalid bases get their own warning.                                                                                                                                                                                                                                        |
| 6. Malformed base drops all CSP resources          | Preserve valid absolute and data sources, and follow HTML's fallback for relative resources. Browser tests cover the actual fallback difference described below.                                                                                                                                                                                                                                                      |
| 7. False hidden/CORS attributes change behavior    | Retain omission for `hidden: false` and `crossorigin: false`, including CORS deduplication and SRI checks. Metadata content, data attributes, and ARIA booleans remain literal values.                                                                                                                                                                                                                                |
| 8. Structured image keys are not global            | Repeated explicit keys move the property to its new image group. Tests also cover transitions between ordinary metadata, roots, and properties.                                                                                                                                                                                                                                                                       |
| 9. Evicted roots leave a stale group pointer       | Evict the old root and all its properties, restore the final surviving image group, and preserve later orphan properties when no image remains.                                                                                                                                                                                                                                                                       |

| 11. Keyed image updates erase unrelated images     | Explicit roots upsert only their matching group across sources. An unkeyed image list still replaces the inherited list; both behaviors are documented and tested.                                                                                                                                                                                                                                                    |
| 12. Module preload default destination differs     | Treat missing `as` as `script` for deduplication, with unit and packed-consumer checks.                                                                                                                                                                                                                                                                                                                               |
| 13. Static builds use an HTTP origin               | Conditional on Astro's `site` configuration, not an unconditional build defect. Packed consumers verify both unconfigured HTTP and configured HTTPS origins. Document setting the public site; forcing HTTPS would produce incorrect sources on HTTP documents.                                                                                                                                                       |

Retain one isolated output build per browser worker to avoid shared fixture state.                                                                                                                                                                                                                                                       |

## Browser boundary for malformed bases

The [HTML base algorithm](https://html.spec.whatwg.org/multipage/semantics.html#the-base-element) falls back to the document URL when a base is malformed or uses `data:` or `javascript:`. Helmet follows that algorithm and warns about the invalid base. With `https://[bad`, the tested Firefox and WebKit use the document URL, while Chromium uses `about:blank` and cannot resolve the relative script. All three still load the absolute and data scripts under the generated policy. The regression permits either measured base behavior while requiring resource execution to agree with it. Applications should fix malformed bases rather than depend on fallback behavior.

These changes preserve the original audit's CSP delivery limit: registering resources does not make a late meta policy protect earlier head elements. The browser server delivers Astro's generated policy as a response header so the tests verify enforcement from the start of parsing.

## Independent review of the follow-up

Independent security, metadata-composition, and compatibility reviews of commit `00f308c` identified three further regressions. Each was reproduced before fixing it.

| Finding                                                                                             | Resolution and regression coverage                                                                                                                                                                                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A head-derived CDN base suppresses standalone SRI warnings when the document origin is unknown.     | Compare resource origins only with the normalized caller document URL. Cover scripts and stylesheets with absolute, scheme-relative, and relative URLs, missing integrity or CORS attributes, and explicit or legacy document origins.                                                                                                                            |
| Replacing an image list can revive ordinary metadata that an earlier explicit image key superseded. | Resolve prior key replacements before removing the inherited image list. Cover keyed image roots and structured properties, repeated source transitions, and canonical/noindex validation.                                                                                                                                                                        |
| Evicting the current image leaves later properties detached from an earlier surviving image.        | Restore the final surviving image group. Cover consecutive evictions, keyed updates in earlier output positions, and replacement-root ownership. Key-map cleanup now checks both the group and item identity, so reusing the same input object cannot erase another group's entry. Frozen shared-object cases verify input immutability and orphan deduplication. |

A packed-consumer page exercises all three reported regressions through the public exports and rendered Astro output. The independent security review also checked 100,000 deterministic script-parser cases (98,625 accepted and 1,375 rejected), with no accepted-content or document-boundary failures. The parser did not change in this follow-up.

The compatibility review confirmed that Astro 5.13.4 exposes an earlier experimental CSP API without `Astro.csp`. Helmet already treats that API as unavailable; the README now states this boundary explicitly rather than implying that every Astro 5 experimental implementation is supported.

The final security and composition reviews found no further actionable issues in these fixes. Their 31 additional direct checks covered document origins, bases, image aliases, shared objects, and keyed composition alongside the complete automated verification recorded in the [remediation note](audit-remediation.md).
